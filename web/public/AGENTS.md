## Purpose

Static files Vite copies to the site root unchanged: the web app manifest, the favicon, the generated PNG app icons, install screenshots and the open font licenses page.

## Map

- `manifest.webmanifest`: hand-written.
- `favicon.svg`, `icons/`: generated by `make icons` from `LOGO` and the palette in `../src/components/pixel-sprites.ts`. Never hand-edit; `make icons-check` (in `make check`) fails when stale.
- `licenses/`: `index.html` (self-contained, inline CSS) and byte-for-byte copies of each `@fontsource` font's LICENSE.
- `screenshots/`: written by `make screenshots`.

## Rules and gotchas

- The manifest, favicon, icons and licenses are precached by the service worker. Screenshots are not: only the browser's install UI fetches them, online. A new top-level file type may need the precache rules in `../src/pwa/shell-rules.ts`.
- Every `@fontsource/*` family imported in `../src/main.tsx` needs its license file here, copied from `node_modules/@fontsource/<family>/LICENSE`, and a link on `licenses/index.html`.
- Manifest icon, shortcut icon and screenshot paths must exist, shortcut `url`s must be app routes, and `theme_color`/`background_color` must match `index.html`'s theme-color and the `--color-background` token.
- Screenshots are 824x1830 and under 200 KB each.
- Paths are absolute from the site root (`/icons/...`).

## Testing

- `tests/web/manifest.test.ts`, `licenses.test.ts`, `png.test.ts` (`make test-web`): add the failing test there first.
- `e2e/pwa/installable.spec.ts` checks installability in a real browser.
