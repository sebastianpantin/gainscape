## Purpose

The Profile tab and everything under it: the user's own profile card and stats, editing profile fields, previewing what friends see (with the public/private switches), and Settings (units, effort input mode, time zone, email and password, PWA install and update, data export, sign-out, account deletion).

## For AI Agents

### Working In This Directory

- Profile rules, validation and Supabase calls live in `../../lib/profile.ts` and `profile-rules.ts`; display shaping in `profile-view.ts`; unit conversion in `units.ts`. Weights are always stored in kg.
- Public and private fields are separate tables or RPCs (`updatePublicProfile` versus `updatePrivateProfile`). A new field must be placed on the correct side, shown on `ProfileCard` only if public, and kept in sync with RLS and the column maps (`PUBLIC_COLUMNS`, `PRIVATE_COLUMNS`) in `web/src/lib/profile.ts`.
- Account deletion and export call Edge Functions (`delete-account`, `export-data`). Changing their payloads needs the integration test updated too.
- Sign-out must keep drafts (`signOutKeepingDrafts`).

### Testing Requirements

- Unit: `tests/web/profile.test.ts` (including the timezone, bodyweight and height helpers), `tests/web/profile-view.test.ts`, `tests/web/local-drafts.test.ts`, `tests/web/units.test.ts`, `tests/web/names.test.ts`, `tests/web/update-flow.test.ts` and `tests/web/install-state.test.ts` (settings PWA controls), via `make test-web`; the version text and the What's new link are asserted in `e2e/whats-new.spec.ts` and `e2e/pwa/offline.spec.ts`.
- E2E (stack needed): `e2e/bodyweight-trend.spec.ts` (trend chart, offline save), `e2e/weekly-goal.spec.ts` (goal in settings, card and streak on Today, a change waits for next week), `e2e/profile.spec.ts` (every field, pounds display, RPE logging, time zone, password, export, delete account), `e2e/a11y.spec.ts` (profile, edit, preview, settings), `e2e/pwa/update.spec.ts`.
- Integration: `tests/integration/profile.test.ts`, `account.test.ts`.
- `use-profile.ts` and `use-optimistic-profile-save.ts` have no unit test of their own; their decisions (`previousValues`, `saveProblemText`) are in `profile-rules.ts`.

### Common Patterns

- Screens call `useProfile`, switch on `state.status`, and push changes through `replace`; settings toggles go through `useOptimisticProfileSave`, which rolls back on failure.
