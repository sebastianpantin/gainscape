# Workout Feature

**Parent context:** `../AGENTS.md`
**Generated:** 2026-10-01 · **Updated:** 2026-10-08

## Purpose

The Train tab at `/`. It logs a workout as an offline-first draft (IndexedDB via `../../offline/`), previews XP per set locally, and on Finish sends the draft to the `complete-session` Edge Function with retries, then navigates to `/reveal` with the returned `SessionSummary`. Its widgets (set rows, effort selector, exercise picker, bodyweight prompt) are reused by history and programs.

## For AI Agents

### Working In This Directory

- Draft shape and mutations belong to `../../offline/draft-format.ts` and `draft-session.ts`. Do not mutate drafts in components; call the functions from `useWorkoutDraft`.
- A finished draft must never be lost or sent twice. Retry, lock and sync semantics live in `../../offline/finish-retries.ts`, `finish-lock.ts` and `sync-workout.ts`; keep `use-finish-sync.ts` a thin adapter and put behavior changes there under test.
- The XP preview is only a hint; the server result is authoritative. `WorkoutScreen` feeds it the `exercise_strength_state` RPC result as of the draft start (`fetchStrengthState`) and the profile bodyweight, the same inputs `complete-session` uses. Keep rules in the domain, not here.
- Another account's draft is kept but never sent (see `OtherAccountDraftNotice`).
- `WorkoutScreen` keys exercise cards by each draft exercise's stable `clientId` and tracks the open Swap picker by it, so removing another exercise, even an identical one, leaves both in place; the picker closes once no card holds its key. Per-workout state (finish problem, Swap picker, focus, discard confirm, strength views, `useRecentLiftSessions` scoped to the user and draft session) resets when the draft's `sessionId` changes, since a replaced draft does not remount the screen.
- Below the finish bar, `Discard workout` (left out on a challenge draft, whose banner has its own) confirms `Discard this workout?` (`Your logged sets will be lost.`), stops the rest timer and calls `discardDraft`.
- Controls between sets must stay 44px touch targets (checked by `e2e/a11y.spec.ts`).

### Common Patterns

- Props-driven small components; screen owns state, widgets are controlled.
- Rate limit and timeout messages use `RATE_LIMITED_CODE` and `waitText` (in `workout-rules.ts`), `REQUEST_TIMEOUT_MS` (from `../../lib/auth-restore.ts`).
