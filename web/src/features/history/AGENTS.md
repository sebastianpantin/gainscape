# History Feature

**Parent context:** `../AGENTS.md`
**Generated:** 2026-10-01 · **Updated:** 2026-10-01

## Purpose

Past workouts under the Log tab: a paged session list and a detail screen where a recent session can be edited or deleted. Edits are sent to the server, which recomputes XP, records and loot.

## For AI Agents

### Working In This Directory

- `HistoryScreen` and `SessionDetailScreen` import `isSessionEditable` from `@domain/edit-window.ts`, the same rule the `edit-session` and `delete-session` Edge Functions apply.
- Put every new edit rule in `session-edit.ts` as a pure function and every save or delete outcome in `session-editor.ts`. Keep `SessionDetailScreen.tsx` to state and rendering.
- Row mapping and uuid checks are in `../../lib/history-rules.ts`; fetches and mutations (`fetchSession`, `editSession`, `deleteSession`) in `../../lib/history.ts`.
- Deleting or syncing must call `forgetLastSummary` so the reveal does not show a removed session.

### Testing Requirements

- Unit: `tests/web/session-edit.test.ts` (`make test-web`) is the place for the first failing test, `tests/web/session-editor.test.ts` for the save and delete flow (fake ports); `tests/web/history-rules.test.ts` covers `invokeWithRetries`, `tests/web/format.test.ts` and `tests/web/effort-labels.test.ts` the moved helpers. Paging is covered by `tests/integration/history-paging.test.ts` (stack needed).
- E2E (stack needed): `e2e/history.spec.ts` (edit a set and see XP change, delete, workout deleted elsewhere, concurrent edit rebase, delete after an edit elsewhere, re-finishing an already saved workout, a save whose refresh fails) and `e2e/a11y.spec.ts`. The server side is covered by `tests/integration/edit-session.test.ts` and `delete-session.test.ts`.

### Common Patterns

- Immutable updates returning a new `SessionEdit`; new set ids come from `withNewSetIds`.
- Failure handling goes through `failureAction` and `failureText` rather than ad hoc branches.
