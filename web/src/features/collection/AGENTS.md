## For AI Agents

### Working In This Directory

- Crafting rules come from the domain (`@domain/crafting.ts`); the server is authoritative, so the UI only pre-checks with `canCraft`.
- Item presentation rules live in `../../lib/item-rules.ts`; data fetches in `../../lib/items.ts` and `../../lib/collection-data.ts`. Do not duplicate them here.
- Adding a tab means editing the `links` array in `CollectionTabs` and a route in `App.tsx`.

### Testing Requirements

- Unit: `tests/web/items.test.ts` (item rules), `tests/web/items-cache.test.ts` (saved items), `tests/web/collection-rules.test.ts` and `tests/web/record-slots.test.ts` (`make test-web`). Collection counting parity with the server runs through `tests/integration/collection-support.ts` and `collection-parity.test.ts` (stack needed).
- E2E (stack needed): `e2e/workout-records.spec.ts` (records and the collection log), `e2e/loot.spec.ts` (items screen, crafting, a former scroll variation in the picker), `e2e/challenges.spec.ts` (Start challenge offline, discard), `e2e/term-help.spec.ts` (progress screen help) and `e2e/pwa/offline.spec.ts` (Items offline), `e2e/custom-exercise.spec.ts` (record card for custom exercises), `e2e/a11y.spec.ts`.

### Common Patterns

- Slot rendering and text live in `record-slots.ts` and `RecordSlots.tsx`; do not rebuild slots inline.
- Views are plain data from `lib/` fetchers; components do formatting only.
