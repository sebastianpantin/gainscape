# offline

**Parent context:** `../AGENTS.md`
**Generated:** 2026-10-01 · **Updated:** 2026-10-09

## Purpose

`web/src/offline/` makes workout logging work without a network. A workout is held as a local draft (one per user) in IndexedDB, with a `localStorage` fallback. When the user finishes, the draft is sent to the `complete-session` Edge Function under a per-user Web Lock, retried with backoff until the server answers, then replaced by a tombstone ("synced" record). Discarding a draft also leaves a tombstone ("discarded" record), so a late write from another tab cannot bring it back, and forgetting an account's draft leaves a short-lived "forgotten" tombstone for the same reason. The server stays authoritative: the draft carries only what the user entered, and XP, records and loot are computed on sync. Most logic is pure or takes injected ports so `tests/web/` can drive it with fake IndexedDB, in-memory storage and fake channels.

## For AI Agents

### Working In This Directory

- **Draft format backward-compatibility rule (from the root `README.md`).** Draft formats must stay readable by the previous build: a new draft format ships only after a release that can already read it, because a tab can keep running the old bundle until it reloads. In practice this is a two-release process. Release A teaches `parseStoredDraft` to read the new version (add it to the accepted set, keep writing the old version). Release B starts writing the new version. Today the code writes `DRAFT_FORMAT_VERSION = 3` and still reads `UPGRADABLE_FORMAT_VERSION = 2`. Never bump the written version and the reader in the same release, and never drop a reader for a version that a deployed build may still write.
- Drafts carry no gear. `complete-session` snapshots the loadout equipped when the draft syncs, so a workout logged offline and synced after a gear change gets the new gear's bonus.
- Any change to `WorkoutDraft` or the stored record shape must keep old records parseable (normalise in `normalisedDraft`/`normalisedSet`) and needs a case in `tests/web/draft-format.test.ts`.
- **The `DraftStore` contract is shared.** Every behaviour of `put`, `markSynced`, `discard`, `forget`, `get` and `userIdsWithDrafts` must be identical in the IndexedDB and `localStorage` stores. Put the decision in `decidePut`/`tombstoneFor` so both reuse it; do not fix one implementation only.
- **Write ordering uses `updatedAt`.** A `put` older than the stored record returns `stale`. Obtain timestamps from `nextUpdatedAt(lastSeen, now)` (strictly increasing per session) and never from raw `Date.now()`. `markSynced` and `discard` write a tombstone with `max(updatedAt, stored.updatedAt + 1)`.
- **A finished draft cannot be silently reopened.** `put` of an unfinished draft over a finished one with the same session id returns `refused_reopen` unless `{ reopen: true }` is passed. A synced or discarded session id is never overwritten (`synced`, `discarded`).
- **Finish lock.** All server sends go through `attemptFinish`, which holds `navigator.locks` `gainscape.finish.<userId>` so two tabs never send the same session twice, and re-reads the store inside the lock (`superseded` if another tab already synced or replaced it). The lock name is also what the service worker update flow waits on (README: the reload banner waits for any running Finish), so renaming it breaks `src/pwa` and `src/sw` behaviour. Without `navigator.locks` it sends unlocked.
- **Sync outcomes are a closed set.** Add new HTTP behaviour in `sendOutcomeFrom` and handle the new `SendOutcome` kind in `startFinishRetries`/`SettledFinish` and in the feature code that renders it. A `retryable` outcome must never be settled.
- **The session id is the idempotency key.** `complete-session` must stay idempotent per `sessionId`; the payload ids (`set.id`) come from the draft. Changing `session-payload.ts` requires the matching Edge Function schema change and an integration test.
- Persistence failures degrade, they do not throw: IndexedDB failure falls back to `localStorage`, a boot that cannot read IndexedDB sets `saveProblem` to `unreadable`, a failure of both to `unsaved`. Keep draft code from throwing into React.
- **Every saved screen cache is per user and forgotten with the device.** Build it with `userCache` in `cache-first.ts`, validate with zod, load it through `loadCacheFirstWhenOffline` (saved after each online load), show the module's `Offline: using your saved …` notice when `fromCache` is true, and add its `forget` to `forgetThisDevice` in `features/profile/SettingsScreen.tsx`. Screens with no cache call `failFastWhenOffline` before their request. Do not change postgrest-js retries globally.
- No comments, `.ts` import extensions, no dependence on `window`/`document` in the pure modules; `draft-boot.ts` and `use-workout-draft.ts` are the only files that touch browser globals directly (`indexedDB`, `localStorage`, `BroadcastChannel`, `navigator.storage`).

### Common Patterns

- Dependency injection through option objects (`DraftSessionOptions`, `FinishAttempt`, `FinishRetryOptions`) so tests supply fake stores, channels, `send`, `retryDelayMs` and `AbortSignal`.
- Pure immutable draft updates: each mutation returns a new `WorkoutDraft`; `updateExerciseAt` (generic over the owner of the `exercises` array) is the shared index-guarded updater and `withSets` (exported, generic over the exercise type) replaces one exercise's sets.
- Records are validated on read (`parseStoredDraft` returns `null` for anything unknown, wrong user or wrong version) so corrupt or foreign data is ignored instead of crashing.
- A single promise chain per session (`enqueue`) serialises all store operations; `flush` waits until the chain stops growing.
- Result unions with a `kind` field: `PutResult`, `SendOutcome`, `FinishAttemptResult`, `FinishStatus`.
