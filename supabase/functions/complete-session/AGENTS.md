# complete-session

**Parent context:** `../AGENTS.md`
**Generated:** 2026-10-01 · **Updated:** 2026-10-08

## Purpose

POST endpoint that accepts a finished workout draft from the web app, validates it, and stores it. Inside the edit window it inserts placeholder sets and replays XP, records and loot; outside it stores a history-only session. A draft may carry a program link and per-set prescription snapshots; they are parsed offline-first, so a bad link or snapshot is dropped instead of rejecting the workout. The response is the stored summary plus `programLinked` and `completedAt`. A draft may also carry `challenge: { challengeId }` for a scroll challenge. Resubmission of the same id returns the stored summary with the stored `programLinked` and `completedAt`, byte for byte.

## For AI Agents

### Working In This Directory

- Server computes effective load via the domain `writableSetFor` and records it as `recordedEffectiveLoadKg` so history-only sessions keep it; never trust client XP.
- Needs `LOOT_SECRET` through `rollNewSessionLoot`.
- The payload shape must match the web draft sync code.
- Offline-first: never answer 4xx for a malformed or duplicate prescription or a malformed `program`. Duplicate refs keep the first set's snapshot (`storableSnapshots`). The rest of the payload is validated as strictly as before.
- A challenge is claimed at sync, never when the draft starts. The scroll is used up whether the verdict passes or fails, and an edit or deleting the session refunds nothing. The client sends only the challenge id; the definition and e1RM snapshot come from the server.
- `410 session_deleted` is unchanged; the web cache appends nothing for it.
