## Purpose

Everything the backend consists of: the local Supabase stack configuration, append-only SQL migrations (schema, RLS, SQL functions), the generated seed, pgTAP database tests, GoTrue email templates and the Deno Edge Functions. `config.toml` is written for the local stack only. The server is authoritative here: Edge Functions compute XP, records and loot and RLS keeps every user inside their own rows.

## For AI Agents

### Working In This Directory

- `config.toml` has values that are only safe locally: `site_url = "https://localhost:5173"`, loopback redirect URLs for `/auth/confirm`, and `[auth.rate_limit]` raised to 1000 so test suites never hit limits, plus `max_frequency = "1s"`. Never run `supabase config push` with this file. `docs/production-auth.md` lists the hosted values.
- `seed.sql` is output. Change `catalog/*.yaml` and run `make catalog`; `make catalog-check` (part of `make check`) fails on drift.
- After any migration change: `make reset`. No generated DB types are used; update the hand-written `*Row` interfaces and `*_COLUMNS` select strings in `web/src/lib/` and the SQL strings in `functions/_shared/stores/` by hand.
- Tables are exposed through the `public` schema with RLS. Server-only objects live in the `private` schema.
- The Supabase CLI is invoked as `npx supabase` (Makefile `SUPABASE` variable); do not assume a global install.

### Testing Requirements

- SQL, grants and policies: pgTAP in `supabase/tests/` via `make test-db` (local stack required, refuses non-local hosts).
- Edge Function behaviour and RPCs through the API: `tests/integration/*.test.ts` via `make test-integration`.
- Seed content: `tests/catalog/` via `make test-catalog`.

### Common Patterns

- Local ports: API 54321, DB 54322, Studio 54323, Mailpit 54324.
- A second worktree stack uses a gitignored `.stack.env` with a distinct `SUPABASE_PROJECT_ID`.
